# wtc 0.1.41

This release lets a collection run its own build of wtc.

## Development builds in a collection

- `wtc dev install` builds the wtc-cli checkout in a collection into
  `.wtc/dev/wtc`. Any `wtc` from this release on that starts inside that
  collection hands over to the dev build while it is the same version or
  newer, so panes, agents and hooks run the code under development without
  PATH changes ([#79](https://github.com/lcorneliussen/wtc-cli/issues/79)).
- `wtc dev status` shows which build is in effect, `wtc dev uninstall` removes
  it, and `WTC_DEV_BUILD=off` skips the handover for one command.
  `wtc --version` names the release a dev build stands in for.
- Dev build versions come from `git describe`: a build past `v0.1.41` sorts
  above 0.1.41 and below 0.1.42. Once the pinned release moves past the build,
  the pinned binary runs itself again and notes this on a terminal.
- The harness compatibility check accepts such dev builds inside the ranges of
  the releases around them.
- `wtc retire` removes a collection's dev build.

## Harness upgrade

Read `wtc release-notes --since <old-pin>` with this binary before changing a
harness pin, and update the pin and compatibility range together. Nothing in
this release needs a harness change. A collection without a wtc-cli checkout
and without `.wtc/dev` behaves as before.
