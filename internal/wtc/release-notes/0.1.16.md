# wtc 0.1.16

This release adds a native `wtc status` command and interactive status view for worktree collections.

## Status views

- Run `wtc status` for a fresh collection snapshot. Use `--json` for structured data, `--md` for agent-readable output, `--ansi` for a terminal table, or `--cached` to read the last completed snapshot without Git or forge calls.
- Use `--tui` or `--watch` for an interactive view with background refresh, scrolling, help, and an archived-PR toggle. Captured output prints one pass and exits. `--procs` shows processes under the herdr session.
- Select a named collection or use explicit `--all` for a workspace view. Scoped runs write JSON, Markdown, and shell-compatible YAML snapshots; workspace views do not write collection snapshots or run other collections' build hooks.
- Status combines local Git state with enlisted and active-branch GitHub or Bitbucket pull-request facts. Stale shared refs are refreshed by age unless `--no-fetch` is set. Forge failures preserve unknown states rather than claiming a passing check or merge.

## Build facts

- An executable `harness/hooks/wtc/status.build.sh` can supply read-only tip and production build facts through a JSON stdin/stdout contract. The TUI displays `T` and `P` cells and can open their HTTP(S) build URLs; use `--no-click` to disable mouse targets.
- The `wtc customize` guide documents the hook contract. Unregistered auxiliary worktrees do not block status when a build hook is present.

## Upgrade

Pin `0.1.16` in the harness's `.wtc-cli-version`, refresh the collection environment, and run `mise install`. Existing status shell entry points remain available while their matching-pin shims are updated.

macOS and Linux archives and checksums are published with this release.
