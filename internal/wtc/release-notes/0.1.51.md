# wtc 0.1.51

On an OpenClaw gateway, the card now suggests the wtc project and
repositories to work in, from what the person types or sends, and starts the
collection, or a new conversation for it from the agent's main session.
Adding repositories no longer ends in a failed reply.

## OpenClaw: wtc projects

- **The card suggests where to work.** In a conversation without a
  collection, the card reads what the person types, once they pause, or
  their latest message, and suggests a wtc project and its repositories:
  "Work in wtc project wtc with wtc-site?". **Start** asks the conversation
  to start that collection, sending a draft along. In the agent's main
  session it asks for a new conversation for the task instead. The gateway's
  decision model makes the suggestion for a sent message when one is
  selected. Until OpenClaw releases decision models, the plugin asks
  OpenAI's Decisions API itself when the gateway has
  `WTC_DECISIONS_OPENAI_API_KEY`; the sent message then goes to OpenAI. A
  draft that has not been sent is only matched by its words, on the gateway,
  as is every message without a decision model
  ([#154](https://github.com/lcorneliussen/wtc-cli/issues/154)).
- **The `openclaw` CLI no longer reports the wtc plugin failing to
  register.** Without a runtime (CLI metadata, setup), the plugin registers
  nothing
  ([#154](https://github.com/lcorneliussen/wtc-cli/issues/154)).
- **No "wtc Collection" bar across every conversation.** The plugin no
  longer registers a header action, which OpenClaw showed as a bar even in a
  conversation without a collection. The card and the session menu open the
  panel ([#154](https://github.com/lcorneliussen/wtc-cli/issues/154)).

## OpenClaw: collections

- **Adding repositories no longer ends in "Couldn't finish this reply".** A
  repository's owner session only holds its worktree, so `wtc add-repo` now
  spawns it with `expectsCompletionMessage: false`. Its start no longer comes
  back to the collection's conversation as an extra turn, which could be
  empty after the agent had already answered and was then shown as a failed
  reply. Workers still report back
  ([#161](https://github.com/lcorneliussen/wtc-cli/issues/161)).

## Upgrade

- **OpenClaw gateways:** install the new `wtc`, then run `wtc openclaw
  install`. Reload open Control UI tabs for the new card.
- **Decision models:** optional. To have OpenAI suggest the project for sent
  messages, give the gateway `WTC_DECISIONS_OPENAI_API_KEY` (a Platform API
  key). Never give it as `OPENAI_API_KEY`, which OpenClaw's chat model could
  use. The plugin's `decisionModel` setting picks the model (`gpt-6-luna`).
