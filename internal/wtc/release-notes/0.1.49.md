# wtc 0.1.49

On an OpenClaw gateway, the repository you ask for now picks the harness: a
collection starts in the harness whose registry lists it, with a worktree of
the harness and of that repository. A repository the harness does not list is
no longer added silently. The agent asks the person whether to add it ad hoc,
register it in the harness, or give it a collection of its own. A collection's
folder now shows which harness it works in.

## OpenClaw: harnesses

- **The registry picks the harness.** Asking for a repository that a configured
  harness lists, by name, URL or `owner/name`, starts the collection in that
  harness, with a worktree of the harness and of that repository. Of several
  harnesses that list some of the repositories, the ones that list all of them
  win; `defaultHarness` decides only between those that are still tied, or
  stands in when none lists them
  ([#138](https://github.com/lcorneliussen/wtc-cli/issues/138)).
- **A repository the harness does not list is the person's choice.** That
  holds whether the harness is the default, the only one or the collection's
  own. `wtc add-repo` stops, and the agent asks the person which of three
  printed commands to run:
  - ad hoc beside the harness, with the new `--ad-hoc` flag;
  - registered in the harness's `.harness-repos.yml` first;
  - a collection of its own (`--harness none`).

  The commands for this collection name it and the chosen harness, so they run
  as printed. A worker is not asked again, because its task already decided
  ([#138](https://github.com/lcorneliussen/wtc-cli/issues/138)).
- **`--harness none` is recorded.** A collection started without a harness
  stays without one: a later `wtc add-repo` of a listed repository does not
  bind it to a harness, and `--harness <name>` is refused
  ([#138](https://github.com/lcorneliussen/wtc-cli/issues/138)).
- **The folder says which harness.** A collection's folder is
  `$OPENCLAW_STATE_DIR/wtc/<harness>/<name>`, or `wtc/ad-hoc/<name>` without
  a harness. A worker's folder sits beside its task's. Folders under
  `wtc-collections/` keep working
  ([#138](https://github.com/lcorneliussen/wtc-cli/issues/138)).

## Upgrade

- **OpenClaw gateways:** install the new `wtc`, then run `wtc openclaw
  install` so that the gateway's plugin and the agent's `wtc` skill match it.
- **Harnesses:** a gateway with one harness, or with a `defaultHarness`, no
  longer puts every new collection in it. Only a repository its registry lists
  picks it. If your collections relied on that default for repositories
  outside the registry, register them, or expect the agent to ask. A harness
  can no longer be called `ad-hoc`.
- **Existing collections** keep their folders under `wtc-collections/`, and
  their recorded harness. New ones get the new layout.
