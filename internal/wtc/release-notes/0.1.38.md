# wtc 0.1.38

## Fixed

- `wtc new` and `wtc add-repo` now invoke the harness `env.pre` and `env.post` hooks before secrets linking and repository initialization. Custom collection aliases and tool routing are available when init hooks first run.
- Environment pre-hook failures stop initialization. Post-hook failures retain the existing warning behavior.

## Compatibility

Harnesses that customize generated environments should use 0.1.38 or later for native collection creation and repository enlistment. Existing command syntax and the explicit `wtc env setup` workflow are unchanged.

Synthetic regression tests cover native creation, enlistment with stale or missing generated environments, preservation of local overrides, and pre-hook vetoes.

See [#61](https://github.com/lcorneliussen/wtc-cli/issues/61) and [#62](https://github.com/lcorneliussen/wtc-cli/pull/62).

## Known issue

Bitbucket review posting/resolution can hit command and JSON-output incompatibilities with `@pilatos/bitbucket-cli` 1.8.3. This lifecycle release does not change that integration; [#60](https://github.com/lcorneliussen/wtc-cli/issues/60) tracks the correction.
