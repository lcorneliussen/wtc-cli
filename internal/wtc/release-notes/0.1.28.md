# wtc 0.1.28

## Status tables

- Repository rows show separate worktree-change (±), ahead (↑), behind (↓), test, and production columns. Test and production columns remain visible even when no build facts have been reported.
- The pull request section is an aligned table with state, checks, merge, review, and title columns. Active work appears first; recently merged rows are quieter while their terminal hyperlinks remain usable.
- Repository names and branches link to their GitHub or Bitbucket pages. PR and build references remain direct terminal links, with color instead of a permanent underline. Build providers can supply a number and direct URL for either forge through the status build hook.
- Tables adapt to narrow terminals. Large ahead, behind, and worktree-change counts keep their full values at normal widths, and mouse targets follow the visible columns.
- Refresh progress stays on one fitted line so the table does not move. The refresh log updates each stage's count in place, and clicking “refreshing” or pressing `l` opens it.
- When a forge lookup fails, the PR table shows `unknown` instead of claiming the PR is open.

These changes apply to the interactive status view and the one-shot terminal table. PR rows in JSON snapshots now carry an optional `state` field; existing fields remain compatible.
