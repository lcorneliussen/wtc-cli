# wtc 0.1.5

This release adds native linking of collection secrets from the machine's control root.

## New command

- `wtc secrets link [--repo <name>] [--dry-run]` links control-root files into matching checked-out worktrees. It refuses any target without a git ignore rule and preserves an existing regular file in the collection's `.harness-backups/` directory.
- `--include-prod` explicitly includes production-capable paths. Declare those paths as repo-relative `prod_paths` in the repository registry, or as `repo/path` values under `[secrets] prod_paths` in `wtc.toml`.
- The command skips repositories absent from the collection and rejects a symlinked destination parent. Harness `secrets.link.pre.sh` and `secrets.link.post.sh` hooks can customize its lifecycle.

When `WTC_CONFIG_ROOT` is unset in the invoking shell, the CLI reads the control-root path recorded in the collection's generated `.env.collection`, then falls back to the documented default.

## Upgrade

Set the harness's `.wtc-cli-version` to `0.1.5`, regenerate the collection environment, and run `mise install` in the collection. Existing shell entry points remain available while their compatibility contracts are checked and converted to CLI shims. The broader command and TUI migration remains in progress; see `MIGRATION.md`.

macOS and Linux archives and checksums are published with this release.
