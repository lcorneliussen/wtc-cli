## Status

- **Status shares one Bitbucket and GitHub allowance.** Build lookups are cached with pull requests. One fetch serves every status pane asking for that record. Bitbucket then allows a short burst and about one call every 8 seconds; GitHub allows a larger burst and about one call every 2 seconds. A rate-limit response pauses that forge and status keeps the last saved record ([#215](https://github.com/lcorneliussen/wtc-cli/issues/215)).
- **Status compares the open list before it fetches a pull request.** Bitbucket's list carries `updated_on`, comment count, task count, and review markers. GitHub's list carries `updatedAt`, the review decision, and check conclusions. A matching stamp keeps the saved detail. A changed stamp is applied from the list. The full pull request is fetched when it leaves that list. One recent Bitbucket pipeline page covers every branch; a branch missing from it keeps its saved build.
- **Status still reads the full record about every 10 minutes.** The list comparison runs first. The full read then runs, and any field it disagrees with is appended to `incremental-misses.log` in the status cache and shown in the refresh log. `WTC_FORGE_FULL_REFRESH` is that interval in seconds; `0` turns it off. A saved Bitbucket build gets the same check against that branch's own pipeline query.
