# wtc 0.1.11

This release adds native repository enlistment for an existing worktree collection.

## New command

- `wtc add-repo <repo> [repo ...]` adds registry repositories to the current collection. `--collection <name>` explicitly selects another collection in the same workspace; `--branch <name>` opts into a branch instead of the detached development tip.
- The command fetches shared bare owners, refreshes the collection environment, links gitignored control-root files, refreshes skills and MCP configuration, and runs each new repository's init hook after those inputs are ready.
- `add-repo.pre` can veto the operation, and `add-repo.post` can react to completion. If a later checkout fails during a multi-repository request, earlier new checkouts are rolled back so the request can be retried.

## Documentation and upgrade

- The embedded `wtc customize` guide and `wtc-add-repo` skill now describe the native command, its hook events, and repository init behavior.
- Pin `0.1.11` in the harness's `.wtc-cli-version`, refresh the collection environment, and run `mise install`. The shell `add-repo.sh` entry point remains available; its matching-pin CLI shim follows separately.

macOS and Linux archives and checksums are published with this release.
