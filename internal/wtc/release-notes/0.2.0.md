# taba/wtc 0.2.0

wtc is now **taba**. This is the first release under the new name. Releases ship a `taba` executable next to `wtc`, the repository is now [lcorneliussen/taba](https://github.com/lcorneliussen/taba), and the Go module is `taba.sh/taba`. `wtc` keeps working, and existing collections, harnesses, pins, files and variables need no changes. See the [rename announcement](https://taba.sh/wtc-is-now-taba/).

## Upgrade

- **From a harness:** run `wtc upgrade --version 0.2.0`, then review and merge the harness change as usual. A 0.1.x binary finds this release through GitHub's redirect from the old repository name. The new archive contains `wtc`, so the upgrade can print these notes.
- **New installs:** `brew install lcorneliussen/taba/taba`, `mise use -g github:lcorneliussen/taba@0.2.0` or a release archive provide both `taba` and `wtc`. `go install taba.sh/taba/cmd/taba@v0.2.0` builds only `taba`; link it as `wtc` if scripts still call that name.
- **Scripts and images that download a release archive by name** need `taba_<version>_<os>_<arch>.tar.gz` from this release on.
- **Harness pins** now render as `github:lcorneliussen/taba` in generated `mise.toml`. A 0.1.x binary regenerating the same collection writes the older `github:lcorneliussen/wtc-cli` key for the same pin. Both resolve to this release, so mise may install it once under each key.

## Rename

- **Releases ship a `taba` executable next to `wtc`.** Both names run the same program. Running `wtc` in a terminal prints a one-line rename notice on stderr. It is skipped for `--json`, non-terminal stderr and shell completion, and `TABA_NO_RENAME_NOTICE=1` hides it. See [invocation names](https://github.com/lcorneliussen/taba/blob/v0.2.0/docs/rename-invocation.md#both-executables) ([#202](https://github.com/lcorneliussen/taba/issues/202)).

- **The repository and module moved.** `lcorneliussen/wtc-cli` is now `lcorneliussen/taba`, and GitHub redirects old clones, fetches and API calls. The module path is `taba.sh/taba` and the main package is `cmd/taba`. Dev builds accept checkouts on either module path. Harnesses that list the repository can rename the entry with `aliases: [wtc-cli]` (next item) ([#202](https://github.com/lcorneliussen/taba/issues/202)).

- **Registry aliases let a repository be renamed without breaking collections.** Rename an entry in `.harness-repos.yml` and list the old name under `aliases:`. Existing collections keep their old folder name, and every command accepts either name, including `catch-up --repos`. The existing `.bare/<old>.git` owner keeps serving all collections and is not cloned again.

  After a rename on the same forge host and owner, catch-up and checkouts point the owner's `origin` at the new registry `remote` and report it once. Forks, transfers, mirrors and local paths are left alone. Port variables are emitted under both names, new collections use the new folder name, and `wtc status` marks old folders "renamed to …". Ad-hoc collections don't support aliases yet; keep using the old URL there. See [renaming a repository](https://github.com/lcorneliussen/taba/blob/v0.2.0/docs/renaming-repositories.md) ([#295](https://github.com/lcorneliussen/taba/issues/295)).

- **Generated environments carry both `WTC_` and `TABA_` names.** The following set `TABA_COLLECTION`, `TABA_AGENT_NAME`, `TABA_CONFIG_ROOT` and `TABA_TOOLCHAIN_PATH` next to their `WTC_` names, with the same values: `.env.collection`, `.env.toolchain`, the `wtc agent-env` snippet, harness and status-build hooks, and new herdr workspaces. Scripts can switch to the new names now. If `.env.collection.local` overrides one of these, set both spellings: the generated `TABA_` value otherwise wins, and the CLI warns that they differ. See [environment compatibility](https://github.com/lcorneliussen/taba/blob/v0.2.0/docs/rename-compatibility.md#generated-environments-carry-both-names) ([#202](https://github.com/lcorneliussen/taba/issues/202)).

- **Status headers and release notes say `taba/wtc`.** The status pane and `status` output now start with `taba/wtc status`, whichever command started them, and the Markdown snapshot reports `CLI: taba/wtc <version>`. Release notes are headed `# taba/wtc <version>`. From 0.3.0 both say `taba` only ([#202](https://github.com/lcorneliussen/taba/issues/202)).

- **Install with Homebrew.** `brew install lcorneliussen/taba/taba` installs `taba` and `wtc` on macOS and Linux. Each release updates the formula in the tap ([#202](https://github.com/lcorneliussen/taba/issues/202)).

- **The README and getting-started guide say taba.** Examples use `taba` and links go to [taba.sh](https://taba.sh/). File and variable names such as `.wtc/` and `WTC_CONFIG_ROOT` are unchanged ([#202](https://github.com/lcorneliussen/taba/issues/202)).

Collections still write their legacy file names, so a collection can be shared with 0.1.x binaries. Removing the `wtc` name is a later major step; this release removes nothing.

## Status

- **Long status views scroll.** Mouse wheel, arrows, Page Up/Down and Home/End scroll while the status header and footer stay visible. Scroll positions clamp after resizing and keep the visible repository or PR across ordinary refreshes. Next-action arrow navigation reveals its focused row, and page scrolling also reaches confirmations and results. Links and service marks in a scrolled view use the displayed row's coordinates ([#316](https://github.com/lcorneliussen/taba/issues/316)).

- **Cached drafts become merged sooner.** When an incomplete open-PR list omits an expired PR, its details are refreshed by number instead of waiting for the longer audit interval. Fresh cache reuse, shared request limits and coalescing are unchanged; unavailable fresh reads stay pending or unknown ([#319](https://github.com/lcorneliussen/taba/issues/319)).

- **Service task state while the runner starts.** When the runner reports starting before task discovery is available, runtime status shows the task as checking, with a diagnostic. Observed task startup, internal runtime controls and service processes are unchanged ([#284](https://github.com/lcorneliussen/taba/issues/284)).

## OpenClaw

- **Async session SDK.** OpenClaw collection discovery, PR watching and sandbox git authorization now await the asynchronous session SDK. The plugin still supports older hosts: it uses the legacy readers only when async methods are absent, and never retries a failed async read through the deprecated API ([#293](https://github.com/lcorneliussen/taba/issues/293)).

- **Renamed repositories keep their gateway project.** After a verified repository rename, existing gateway project IDs are reused, even when clone folders and older collection registries keep their old names. Registry aliases and permitted sandbox metadata resolve old and new names without another clone or changed worktree paths ([#318](https://github.com/lcorneliussen/taba/issues/318)).

- **Evicted checkouts can be restored.** Collection cards and sidebars mark evicted, recoverable checkouts and offer per-repository and collection restore actions. Native admin recovery keeps recorded identities and saved changes; progress and failures appear in the Action log. Refreshing status never restores a checkout or extends its activity. Collection lifetime protection is separate ([#326](https://github.com/lcorneliussen/taba/issues/326)).

- **Repository identity survives a missing checkout.** Repository identity and forge icons stay when a session checkout is unavailable, unknown forges get a repository glyph, and the collection view stays when its status command fails. No checkouts are recreated automatically ([#310](https://github.com/lcorneliussen/taba/issues/310)).

- **Actions share one alignment rail.** Per-row `⋯` menus list alternatives and blocked reasons; the header menu keeps collection-wide catch-up, recovery and push preparation when another action is primary. The primary action stays right-aligned, more eligible actions appear inline when there is room, and the rest sit behind a left-side `⋯` menu ([#326](https://github.com/lcorneliussen/taba/issues/326)).

- **The Collection uses the current taba mark.** Service controls share a compact rail: bulk start and stop sit beside the Services heading, tunnel buttons no longer enlarge rows, and truncated service states show their full label on hover. Start controls use an outlined play icon with a quiet hover cue ([#297](https://github.com/lcorneliussen/taba/issues/297), [#321](https://github.com/lcorneliussen/taba/issues/321)).

- **Tunnel chooser.** It follows the app theme, opens above its control when there is room, and supports keyboard navigation and dismissal. Narrow views fold several tunnel links beneath their service, long links are truncated with an ellipsis, and standalone-tunnel repair controls keep their room ([#302](https://github.com/lcorneliussen/taba/issues/302)).

- **Controls stay stable during refreshes.** Collection controls, focus and open menus no longer reset on unchanged host updates and routine refreshes. Clock ticks update age labels in place; real status changes and completed actions still refresh their controls ([#313](https://github.com/lcorneliussen/taba/issues/313)).
