# wtc 0.1.4

This release adds native commands for independent local pull request reviews. It builds on v0.1.3 without changing the harness installation method.

## New review commands

- `wtc review status <repo> [pr]` reads the newest review status and checks it against the current pull request head. `--trusted-local` also requires a local posting receipt.
- `wtc review ready <pr> [--repo <repo>]` checks the current trusted review gate before promoting a draft pull request.
- `wtc review bundle <repo> [pr] --public --no-catch-up` builds a public review bundle from committed refs. It uses generic concerns from the base commit or versioned CLI defaults for a bootstrap review.
- `wtc review run <bundle>` starts separate headless concern reviewers, aggregates their findings with a lead pass, and writes a machine-readable verdict.
- `wtc review post <bundle>` posts progress and results, deduplicates inline findings, and records a local receipt after posting succeeds. A failed inline post leaves the summary pending.
- `wtc review resolve <bundle>` can reply to and resolve inline threads. With no filters, it resolves all unresolved threads in the bundle.

## Current scope

The native bundle requires `--public --no-catch-up`. Private snapshots, local concern overlays, prior-round context, catch-up, and integrated runner posting remain in the migration inventory. Existing harness scripts continue to cover those workflows.

## Upgrade

Set the harness's `.wtc-cli-version` to `0.1.4`, regenerate the collection environment, and run `mise install` in the collection. The binary stays collection-local through the generated `mise.toml`; no global installation is needed. See `MIGRATION.md` for remaining command and compatibility work.

macOS and Linux archives and their checksums are published with this release.
