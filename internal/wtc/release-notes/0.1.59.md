# wtc 0.1.59

`wtc upgrade` moves a harness to a newer wtc release and rolls it out. A collection keeps one focus: parallel work goes to a collection of its own, and what a sub-session leaves in its own worktree shows in the OpenClaw card under its repository, to merge in, review or discard. (0.1.58 was tagged but never released; this release has its changes.)

## OpenClaw: one focus per collection, sub-sessions shown

- **Parallel work is a collection of its own.** A collection has one branch
  and one pull request per repository. The skill and the instructions have
  the agent propose a new conversation with its own collection for parallel
  work or a second pull request, instead of a worker. `wtc add-repo --worker`
  still works but is deprecated
  ([#194](https://github.com/lcorneliussen/wtc-cli/issues/194)).
- **Sub-sessions show under their repository.** A child session with a
  worktree of its own, whether a wtc worker or one OpenClaw or the agent
  spawned, is a sub-row under the repository, compared with the collection's
  checkout instead of the forge: ± its uncommitted files, with a tooltip
  saying which the collection has the same, which differ and which only it
  has; **↑** merges its commits in; **↓** catches it up; **✕** discards it.
  It never has a pull request.
- `wtc catch-up --from <branch>` merges another branch of the repository by
  its name, and `wtc status <name> --sub <worktree>` compares a worktree with
  the collection's.
- On a worker's branch `wtc publish` refuses, and in its collection
  `wtc svc` won't add, start or provision services; `wtc catch-up` there
  merges the collection's branch.
- **A sub-session's uncommitted files go to the conversation.** Clicking
  their count asks it to compare them with its own checkout and take over
  what is still wanted. ↓ waits until there are none.

## Harness upgrades

- **`wtc upgrade` moves a harness to a newer wtc release.** Run in a
  collection of the harness, it resolves the latest release, or the one given
  with `--version`, and bumps `.wtc-cli-version` and the `wtc.toml`
  compatibility range together. It then refreshes the collection's mise
  config, installs the release, and prints that release's own notes since the
  old pin, ready to decide what to adapt or adopt. It commits nothing.
  `--dry-run` writes nothing and reads the published release notes
  ([#163](https://github.com/lcorneliussen/wtc-cli/issues/163)).
- **`wtc upgrade --rollout` rolls a merged upgrade out.** It catches every
  collection's harness up to the merged tip and runs `mise install` there,
  leaving collections with a dirty harness, a conflicting branch, or a busy
  agent to their owners and listing them
  ([#163](https://github.com/lcorneliussen/wtc-cli/issues/163)).

## Catch-up

- **`--idle-only` and `--install-tools`.** `wtc catch-up --idle-only` leaves
  a collection whose herdr agent is working or blocked to that agent, as
  `needs-owner`. `--install-tools` runs `mise install` after a harness's
  environment refresh
  ([#163](https://github.com/lcorneliussen/wtc-cli/issues/163)).
- The `wtc-catch-up` skill no longer says that only new collections get a
  regenerated `.env.collection`; `wtc env setup` refreshes existing ones.
