# wtc 0.1.62

This release makes next actions more compact, explains status evidence more
clearly, discovers services before their first start, and adds conservative
retirement assessments. Independent reviews now finish locally when progress
posting fails. The executable, release archives and plugin identity remain `wtc`.

## Status and next actions

- **Choose and run one next step per repository.** Status exposes recommendations,
  alternatives and blocked reasons while retaining `next`. The Collection card,
  panel and status TUI can preview mixed selections, recheck each target and
  dispatch a single step per repository. Shared operations are serialized;
  selected author tasks use one prompt per conversation. Dispatch acceptance
  means pending completion. Cancellation stops queued work, and unavailable
  gateway review jobs are explicit. Automatic continuation remains separate
  ([#179](https://github.com/lcorneliussen/wtc-cli/issues/179)).
- **Compact controls keep the next step visible.** Repository, branch, changes,
  PR and action occupy stable groups and separate columns where width permits.
  Small outlined actions stay in the collapsed card's top bar with hover and
  focus feedback. A shortcut runs the captured recommendations; alternatives
  and mixed selections appear on demand. The status TUI keeps a compact hint
  until `n` opens actions. Agent handoff receipts identify the owning
  collection's author pane; busy, missing or ambiguous destinations are
  explicitly unsent ([#260](https://github.com/lcorneliussen/wtc-cli/issues/260)).
- **Catch-up runs on the first click or Enter.** The explicit action supplies the
  timing decision for mechanical catch-up, with active-author and conflict
  checks preserved. Gateway catch-up merges locally; a separate personal-account
  **Update PR** / **Push** action publishes the merge. Publication retains its
  selection preview, account checks and confirmation. Refreshing a view runs
  no actions.
- **Progress and PR history are easier to inspect.** Running rows show one phase;
  named completion controls open an **Action log** in the sidebar. That log lasts
  for the current browser session, and reloading does not resume unfinished work.
  Other active PRs appear as muted number links; **archived PR** counts open the
  full collection PR list. Baseline rows say **at main** (or the configured base),
  with hover text distinguishing untouched task branches from detached HEAD.
  See [OpenClaw actions and publication](https://github.com/lcorneliussen/wtc-cli/blob/v0.1.62/docs/openclaw.md).
- **Clearer collection sidebar.** Actions have their own row below the collection details. Services precede the action log, and section headings share the same emphasis.
- **See the actual running CLI version.** The live status header has a muted
  version suffix, available before the first refresh and linked to stable
  release notes in supporting terminals. It may clip in narrow terminals.
  Development, prerelease and unknown builds do not invent release URLs.
  Local text and JSON snapshots record their producer's version; cached rows
  never replace the live TUI's running version. Dev source freshness,
  replaced-running-binary detection and ignored-build diagnostics remain open
  under [#92](https://github.com/lcorneliussen/wtc-cli/issues/92). See
  [status version details](https://github.com/lcorneliussen/wtc-cli/blob/v0.1.62/docs/status-version.md).
- **Explain residual squash history.** Ahead counts name their reference and
  basis, gone upstreams are marked, and retained merged branches distinguish
  full historical landing, follow-up commits and unknown evidence. Compatible
  PR records retain matching head/merge observations. Raw ahead/behind counts
  remain commit counts; these diagnostics grant no new push, detach or prune
  authority. Existing landing and ref-preservation guards remain in place;
  residual counts alone do not establish destructive loss. See
  [squash landing evidence](https://github.com/lcorneliussen/wtc-cli/blob/v0.1.62/docs/squash-status.md)
  ([#229](https://github.com/lcorneliussen/wtc-cli/issues/229)).
- **Resolve verified enlisted repository aliases.** PR lookup and branch
  association, including retained-merge next actions, accept verified `repo` /
  `ext.repo` aliases. New enlistments share a repository key, legacy rows and
  merge markers remain readable, and ambiguous repository or worktree identities
  are not guessed. See [repository identity rules](https://github.com/lcorneliussen/wtc-cli/blob/v0.1.62/docs/enlisted-repository-identity.md)
  ([#249](https://github.com/lcorneliussen/wtc-cli/issues/249)).

## Publication and review

- **Preserve proposed Bitbucket PR descriptions.** The card forwards the proposed
  description to Bitbucket plugin **0.3.4 or later**, which confirms the exact
  text when creating a PR. Older publishers request an upgrade instead of
  dropping the description. Later pushes preserve existing PR text.
- **Recognize successful pushes.** OpenClaw publication status prefers newer
  remote-tracking evidence over an older publication marker; only commits after
  the newer pushed head count as unpublished. A publisher's local-status warning
  stays visible alongside the successful push and PR.
- **Show exact-head PR pipeline failures.** Bitbucket status includes
  pull-request pipelines in branch build selection and aggregates checks for
  the exact PR head. Review bundles capture check evidence, report confirmed
  failures and distinguish unavailable evidence from passing checks and unknown
  required-check policy. See [PR check evidence](https://github.com/lcorneliussen/wtc-cli/blob/v0.1.62/docs/pr-check-evidence.md)
  ([#184](https://github.com/lcorneliussen/wtc-cli/issues/184)).
- **Finish independent reviews after progress-post errors.** Concerns and the
  lead still run locally, completed results remain available, and the command
  reports posting and execution errors at the end. After an ambiguous progress
  write it makes no further automatic posting attempts. A local create-intent
  marker blocks duplicate creates across uncertain retries; failed updates
  retain the saved comment ID. Inspect and reconcile remote state before an
  explicit retry. A local pass does not establish a posted or trusted review.
  Full Bitbucket transport, writable-contract certification and automatic
  recovery of an unknown created ID remain open under
  [#60](https://github.com/lcorneliussen/wtc-cli/issues/60). See
  [progress failure and recovery details](https://github.com/lcorneliussen/wtc-cli/blob/v0.1.62/docs/review-progress-errors.md).

## Services and retirement

- **Discover declared services before their first start.** Service lists and
  workspace-wide status include shared and collection-local task declarations,
  including tasks in newly added repositories. New tasks appear as
  `unconfigured`; existing runtime and tunnel observations keep precedence.
  Declaration discovery does not run hooks, source environment files, render
  configuration, write generated state or start a runner. See
  [service discovery](https://github.com/lcorneliussen/wtc-cli/blob/v0.1.62/docs/service-discovery.md)
  ([#232](https://github.com/lcorneliussen/wtc-cli/issues/232)).
- **Inspect conservative retirement readiness.** Status includes observed
  blockers and unknown checks for each selected collection. `wtc retire
  [collection] --dry-run` reads fresh evidence and explains preservation and
  follow-up work, with optional bounded Claude JSONL transcript hints. The
  assessment emits `blocked` or `unknown` while archive, forge/delivery and
  external-resource coverage remain incomplete. Dry-run is read-only;
  transcript text is an untrusted hint. No automatic archive discovery or
  cleanup policy is enabled, and execution retains its fresh preflight checks.
  See [retirement assessment coverage](https://github.com/lcorneliussen/wtc-cli/blob/v0.1.62/docs/retirement.md)
  ([#250](https://github.com/lcorneliussen/wtc-cli/issues/250)).

## Compatibility and adoption

- **Existing collections can use `.taba/config` and `.taba/dev`.** Each namespace
  is selected independently with legacy-first precedence. Normal and gateway
  discovery, registry updates and early dev handover honor the selected inputs.
  Dev removal clears both slots without following linked parents; retirement
  clears both local registry slots and checks retained discovery markers before
  teardown, preserving hand-written configuration. Fresh collections, installed
  dev builds and rendered defaults keep legacy paths. Runtime, watcher and
  review namespaces remain further phase-0 work; there is no automatic migration
  or need to rename a working collection. See [collection directory inputs](https://github.com/lcorneliussen/wtc-cli/blob/v0.1.62/docs/rename-collection-directories.md)
  ([#201](https://github.com/lcorneliussen/wtc-cli/issues/201)).
- Update the harness CLI pin and compatibility range together, preserve local
  policy and overlays, and compare overridden skills with the shipped defaults.
  Follow the [harness upgrade guide](https://github.com/lcorneliussen/wtc-cli/blob/v0.1.62/docs/release-notes.md#upgrade-a-harness)
  for environment, tool and generated-guidance refresh steps.
- For OpenClaw, install the matching CLI and run `wtc openclaw install` to refresh
  and reload its embedded plugin, then reload open Control UI tabs. Proposed
  Bitbucket descriptions also require the compatible publisher noted above.
  Existing host requirements are unchanged; this release adds no host-version
  certification. See [OpenClaw upgrades](https://github.com/lcorneliussen/wtc-cli/blob/v0.1.62/docs/openclaw.md#upgrade).
